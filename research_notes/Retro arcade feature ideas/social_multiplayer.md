# Social and multiplayer features for a serverless retro arcade browser game (Galaga-style shooter + Tetris clone)

Context: plain HTML/JS/Canvas, also wrapped as an Android WebView app. The Tetris clone already has a date-seeded "Daily Challenge" with a local best score. Effort ratings (Low/Medium/High for one JS developer) are the researcher's judgment and are listed under Inferences, not as sourced facts.

## Local multiplayer formats (alternating, same-screen co-op, side-by-side versus) and input methods (one keyboard, one phone, gamepads)

### Takeaway
Alternating "Player 1 / Player 2" turns are trivial to add but are historically a weak social format (a strong P1 can make P2 wait the whole game), so they suit pass-and-play on one phone. Real-time formats (two-ship co-op in the shooter, side-by-side garbage battle in Tetris) carry the social energy and work best with one keyboard split in two or with gamepads. The Gamepad API is Baseline "widely available" since 2017, but gamepads appear only after a button press and need polling each frame.

### Cited Findings
- Galaga supports one player or two players taking alternating turns; sources note two-player mode was unpopular because an experienced first player could finish the whole game before the second player's first turn — [Wikipedia: Galaga](https://en.wikipedia.org/wiki/Galaga)
- Galaga's signature mechanic: a Boss Galaga can capture the player's ship with a tractor beam. Shooting the boss while it dives frees the ship, which docks to form a "dual fighter" with double firepower and a hitbox twice as wide. Losing one half leaves the other flying. Shooting the captive scores points — [Wikipedia: Galaga](https://en.wikipedia.org/wiki/Galaga)
- TETR.IO versus mechanics that could be copied into a local battle: combo multiplier (attack = base × (1 + 0.25 × combo)), Back-to-Back charging/chaining bonus lines, an "Opener Phase" (first 14 pieces cancel incoming garbage at 2x), "Windup" (attacks of 8+ lines show an alert and arrive in chunks of up to 4), and a "Clutch Clear" rescue rule — [TetrisWiki: TETR.IO](https://tetris.wiki/TETR.IO)
- TETR.IO custom rooms let the host toggle combo/B2B systems, rounding, spin bonuses, preview count (1–6) and opener length. 3+ player rooms use Tetris 99-style targeting. QUICK PLAY "mods" (No Hold, Messier Garbage, Invisible, Double garbage, etc.) work as opt-in difficulty modifiers — [TetrisWiki: TETR.IO](https://tetris.wiki/TETR.IO)
- Tetris 99 targeting modes (KOs: aim at players closest to dying; Badges: aim at the leader; Attackers: counterattack whoever targets you; Random). KO badges boost outgoing garbage, up to double with four full badges. Eliminating a badge-holder steals their badges — [Destructoid](https://www.destructoid.com/the-depth-of-tetris-99s-mechanics-do-the-impossible-improve-a-perfect-game/); [Siliconera](https://www.siliconera.com/always-remember-to-choose-your-targets-in-tetris-99/); [Shacknews](https://shacknews.com/article/110011/tetris-99-controls-how-to-play-and-strategy)
- Gamepad API: `gamepadconnected` fires on window. If a pad was already connected, the event fires only when the user presses a button or moves an axis. Read state by polling `navigator.getGamepads()` every frame (for example in the requestAnimationFrame loop) and re-reading by `index`, not by holding old references. `mapping === "standard"` means the browser remapped the pad to the standard layout. Buttons expose `pressed` and analog `value`. Axes run from -1 to 1 — [MDN: Using the Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API)
- Gamepad API compatibility: Baseline "widely available", working across browsers since March 2017. `Gamepad.timestamp` is not supported in Firefox. Firefox exposes gamepads only after the user interacts with one while the page is visible (anti-fingerprinting). After that, other connected pads become visible — [MDN: Using the Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API)
- `getGamepads` is restricted to secure contexts (HTTPS) and can throw SecurityError if blocked by a Permissions Policy. web.dev describes browser support as "universally great" on desktop and mobile — [MDN: Gamepad](https://developer.mozilla.org/docs/Web/API/Gamepad); [web.dev: Gamepad](https://web.dev/articles/gamepad)
- No current source confirmed Gamepad API behaviour specifically inside Android System WebView (MDN lists a WebView Android column, but the value could not be retrieved) — [MDN: Gamepad](https://developer.mozilla.org/docs/Web/API/Gamepad)
- Couch co-op design writing found by search was low-quality SEO content. Its only recurring, plausible point is that shared physical space enables instant visible reactions and lowers pressure for mixed-skill groups. Treat it as weak evidence — [example page](https://views.washingtonian.com/vie/couch-co-op-games-where-friendship-levels-up-ejvectors-rise)

### Inferences
- **Alternating 2P (both games)**: store two player states and swap on death, as in arcade play. Best fit for pass-and-play on one phone (no extra input needed). To avoid the Galaga "P2 waits forever" problem, swap on each lost life (arcade style) or offer a "turn per stage/per 40 lines" variant. Effort: **Low**.
- **Same-screen co-op shooter (two ships)**: two ship entities, shared or separate lives, and keyboard split (WASD+Space vs arrows+Enter) or gamepads. Galaga's capture mechanic gives a natural social hook: the partner can rescue a captured ship, or a "dual fighter" can be formed by docking both players. Effort: **Medium** (collision, respawn, HUD, balance of enemy count).
- **Side-by-side Tetris versus (2 boards, garbage)**: refactor the board into an instantiable object, render two boards, and add a garbage queue with cancellation and a simple attack table (single 0, double 1, triple 2, tetris 4, plus combo/B2B bonus inspired by TETR.IO). A one-keyboard split is workable, but key-rollover/ghosting on cheap keyboards can drop simultaneous presses (general knowledge, unsourced; test). On one phone, side-by-side is impractical except on tablets in landscape. Gamepads are the best input. Effort: **Medium**.
- **3–4 player Tetris with targeting** (Tetris 99-lite): only feasible with gamepads. Shrink boards and add a KO/badge rule. Effort: **Medium–High**.
- Gamepad support: poll in the existing game loop, map the standard layout (D-pad 12–15, A=0, B=1), show a "press any button to join" lobby (this also satisfies the user-gesture exposure rule), and assign pads to P1/P2 by join order. Effort: **Low–Medium**. Test in the Android WebView with a Bluetooth pad before promising support.

### Gaps
- No authoritative Game Developer/GDC source was found on why couch co-op is fun. The search returned only SEO filler.
- No source found on Puyo Puyo Tetris handicap options specifically.
- Android WebView Gamepad API status not confirmed by a primary source. It needs a device test.
- No sourced data on keyboard ghosting limits for two players sharing one keyboard.

## Asynchronous competition without a server (share codes/URLs, daily/weekly seeds, ghost replays, challenge links) and pitfalls

### Takeaway
Daily seeded runs plus a Wordle-style spoiler-free text share are the highest value-per-effort social features. They rely on a shared, fixed seed and a share format that pastes cleanly into any chat. Challenge links (seed + target score) are cheap. Ghost replays need a deterministic fixed-timestep simulation, so they cost more. The main pitfalls are cross-engine floating-point differences in transcendental Math functions, frame-rate-dependent updates, trivially forgeable client-side scores, and long URLs failing in mobile chat apps.

### Cited Findings
- Wordle's share grid began with players posting emoji grids themselves. Wardle then added a share button. The grid shows the result pattern without the answer, so it is spoiler-free and pasteable anywhere (Twitter, group chats, Slack). One puzzle per day means everyone works on the same word, which builds community — [Know Your Meme](https://knowyourmeme.com/memes/39248); [AOL/TechCrunch](https://www.aol.com/news/wordle-brought-tens-millions-users-150000203.html); [beastoftraal analysis](https://beastoftraal.com/?p=19327)
- Wordle brought "tens of millions" of new users to the New York Times — [AOL/TechCrunch](https://www.aol.com/news/wordle-brought-tens-millions-users-150000203.html)
- Spelunky HD Daily Challenge: the generation seed is constant for all players that day, there is one attempt per day, and scores are compared on the leaderboard. Random elements that could unfairly swing results (the gambling wheel) are disabled — [Spelunky Wiki](https://spelunky.fandom.com/wiki/Daily_Challenge_Mode_(HD))
- Critique: a single attempt can distort play (too cautious or too risky) in a risk-management game — [The Ludite](https://theludite.com/2014/06/23/spelunky-when-scoring-goes-bad/)
- Game Developer "The 24-hour ticket" (Caveblazers, Dead Cells, OlliOlli devs): daily runs work as a shared-seed puzzle with a "perfect line". Caveblazers reports a large daily player base with small drop-off. Dead Cells sees about 7,000 daily runs a day. Design choices differ: Caveblazers allows one attempt ("players value their lives"), Dead Cells allows unlimited attempts and keeps the best (more welcoming), and OlliOlli allows unlimited practice and then one recorded attempt. One developer called the daily mode among the easiest big features to build. OlliOlli used daily runs to give players a taste of later content — [Game Developer](https://www.gamedeveloper.com/design/the-24-hour-ticket-examining-daily-runs-)
- Determinism: MDN warns that the precision of many Math functions is implementation-dependent. Different browsers, or the same engine on another OS or CPU, can return different results. Rune made JS deterministic by rounding Math results with `Math.fround` — [Rune blog](https://developers.rune.ai/blog/making-js-deterministic-for-fun-and-glory/)
- The `trigfills` package provides cross-browser-consistent sin/cos/tan etc. (better than float32 accuracy). Gaffer On Games warns that expecting identical floating-point results across compilers or architectures is naive — [trigfills](https://classic.yarnpkg.com/en/package/trigfills); [Gaffer On Games](https://new.gafferongames.com/post/floating_point_determinism/)
- A Babylon.js developer reported only tiny float differences across platforms and mitigated them by truncating values and resyncing periodically — [html5gamedevs](https://www.html5gamedevs.com/topic/32258-proposal-implementing-deterministic-lockstep-for-physics-and-animations)
- URL length: Chrome's cap is reportedly about 2 MB (secondary reports), but the common compatibility rule is under about 2,000 characters. A developer reported long links not being clickable in WhatsApp mobile while working on desktop. No official WhatsApp limit is published — [nuqs limits](https://nuqs.dev/docs/limits); [codemia](https://codemia.io/knowledge-hub/path/What-is-the-maximum-length-of-a-URL-in-different-browsers); [Glide forum](https://community.glideapps.com/t/share-link-to-current-screen-links-are-too-long/35968); [Bird docs](https://bird.com/docs/guides/whatsapp/message-types/interactive/cta-url-buttons)
- Client-submitted scores can be forged. Anyone can extract the client config and script requests — [Firebase App Check docs](https://firebase.google.com/docs/app-check); [dev.to Spark vs Blaze](https://dev.to/androve2k/spark-vs-blaze-the-firebase-pricing-guide-i-wish-id-read-sooner-onb)

### Inferences
- **Wordle-style result share (Daily Tetris and a new Daily Shooter)**: build a short text block, for example "RetroTetris Daily #123 — 48,200 pts, 112 lines, Lv 9" plus an emoji mini-chart (for example one block per minute showing lines cleared, or for the shooter the stage reached with hearts for lives). Use `navigator.share()` with a clipboard fallback. It is spoiler-free by design. Effort: **Low**. Highest ROI.
- **Daily seed for the shooter**: seed a PRNG (mulberry32/sfc32) with the date for wave order, enemy dive choices and power-up drops. Replace all `Math.random()` in gameplay with the seeded PRNG and keep a separate unseeded RNG for cosmetics. Consider a "weekly" seed too. Decide the attempt rule (OlliOlli model: unlimited practice plus one "official" attempt is a good compromise). Use UTC date so friends in different time zones share a seed, or accept a local date and say so. Effort: **Low–Medium**.
- **Challenge-a-friend link/code**: `#c=<base64url of {game, mode, seed, score, name, version}>` plus a short checksum (for example a 32-bit FNV/CRC over the payload and a secret salt). This deters casual URL editing only; anyone reading the JS can forge it. Keep it under about 200 characters, use the URL fragment (`#`) so nothing is sent to a host, and also offer a 6–10 character copy-paste code for the Android app. Include a game version so old links can be refused when the generator changes. Effort: **Low**.
- **Ghost replays**: record only inputs per fixed simulation tick (for example 60 Hz fixed timestep decoupled from rAF), plus seed and version. Replay by re-running the simulation. Tetris is integer-grid and naturally deterministic once gravity and lock timing are tick-based. The shooter is at risk if movement uses `Math.sin/cos` for dive curves; precompute path tables, use integer/fixed-point positions, or wrap trig in `Math.fround`/trigfills. Store a state checksum every N ticks to detect desync. Run-length-encode inputs and compress (for example lz-string). A full replay will usually exceed safe URL length, so share it as a file or copy-paste blob rather than a link, or show the ghost only for your own best local run. Effort: **Medium** for Tetris, **Medium–High** for the shooter.
- **Cheating**: without a server, any score can be forged. Frame the feature as a friendly rivalry among people who trust each other, not a ranked ladder. A replay-verified challenge (the recipient's client re-simulates the sender's inputs to confirm the score) is the strongest serverless check, but it requires full determinism.

### Gaps
- No primary Chromium source located for the 2 MB URL cap. No official WhatsApp/Telegram URL limits found.
- No current (2024–2026) measurements of whether V8, SpiderMonkey and JavaScriptCore still differ on `Math.sin`. The sources are older.
- No data found quantifying how much Wordle-style sharing raises retention in small indie browser games specifically.

## Peer-to-peer online play with no game server (WebRTC data channels, signalling options, latency, rollback vs delay netcode)

### Takeaway
WebRTC data channels can carry inputs browser-to-browser, but setup still needs signalling. Options are a free broker (the PeerJS cloud PeerServer), manual copy-paste or QR exchange of SDP, or your own tiny server. Roughly 10–25% of sessions can't connect directly and need a TURN relay, which costs money or must come from a third party. For a 2-player Tetris battle, simple input/garbage-event exchange (not even lockstep) is enough. For a co-op shooter, delay-based lockstep is realistic. Full rollback is High effort.

### Cited Findings
- `createDataChannel` options: `ordered` (default true), `maxRetransmits` or `maxPacketLifeTime` (not both) for unreliable mode, and `negotiated` + `id` for pre-agreed channels. Defaults are reliable and ordered — [MDN: createDataChannel](https://developer.mozilla.org/en-US/docs/Web/API/RTCPeerConnection/createDataChannel)
- PeerJS uses a "PeerServer" for session metadata and candidate signalling. You can use the cloud one or run your own. `peer.connect(id)` returns a DataConnection with `send()` and an `on('data')` event — [PeerJS docs](https://peerjs.com/docs/); [peerjs-server repo via PeerJS GitHub](https://github.com/peers/peerjs)
- Manual signalling works: client A creates an offer, B pastes it and returns an answer, and A applies it. ICE candidates must be included, so you wait for ICE gathering to finish before generating the code. Payloads are large, so projects deflate+base64 or use lz-string. Codes reveal network info (IPs), so they should not be posted publicly — [serverless-webrtc-testbench](https://github.com/fcivaner/serverless-webrtc-testbench); [DEV: manual SDP](https://dev.to/hexshift/building-a-minimal-webrtc-peer-without-a-signaling-server-using-only-manual-sdp-exchange-mck); [@sctlib/rtc](https://npmjs.com/package/@sctlib/rtc)
- QR-code signalling exists (serverless-webrtc-qrcode) but is described as clumsy. One experimenter found scanning 4 QR codes in order tedious — [serverless-webrtc-qrcode](https://github.com/dcerisano/serverless-webrtc-qrcode); [lilting.ch](https://lilting.ch/en/articles/webrtc-qr-signaling)
- Manual exchange is timing-sensitive. One Android user reported that ICE gathering failed if the answer wasn't passed back quickly — [serverless-webrtc-android](https://github.com/SpacebitLabs/serverless-webrtc-android)
- NAT traversal: estimates of sessions needing a TURN relay range from about 10–15% (Twilio: about 85% work with STUN alone) to 20–25% (Getstream citing Chrome UMA). Mobile carrier-grade NAT is usually symmetric, which pushes mobile users toward TURN. One team reports about 5% fail entirely. Most figures are vendor blogs — [Twilio](https://twilio.com/en-us/stun-turn); [Getstream](https://getstream.io/resources/projects/webrtc/advanced/stun-turn/); [Metered](https://www.metered.ca/blog/what-is-a-turn-server/); [omr.it.com](https://omr.it.com/blog/webrtc-p2p-messaging-nat-traversal-production/)
- Delay-based netcode waits for the remote input before advancing a frame, so input latency scales with ping (for example 3–5 frames at 100 ms). Rollback simulates ahead with predicted inputs (repeating the last input is right about 99% of the time per a GGPO talk) and re-simulates on misprediction. It requires a deterministic simulation with save/load state and fast multi-frame resimulation — [Infil netcode explainer](https://words.infil.net/w02-netcode-p5.html); [Wikipedia: Netcode](https://en.wikipedia.org/wiki/Netcode); [Supercraft explainer](https://crux.supercraft.host/blog/rollback-netcode-explained/)
- WebRTC in Android WebView: old sources (Android L era) state WebView gained WebRTC from Chromium 36. A recent sample shows WebRTC working in WebView, but camera/mic permissions need native handling. Data channels need no media permissions — [OnSIP](https://onsip.com/blog/chrome-webview-on-android-l-offers-new-opportunities-for-webrtc-developers); [Android265WebView](https://github.com/mbobiosio/Android265WebView)

### Inferences
- **Online Tetris versus (2 players)**: each client runs its own board and sends only events (piece locked, lines sent, topped out) plus a low-rate board snapshot for the opponent mini-view. Latency barely matters because garbage already has a delay. No determinism is required beyond a shared piece seed for fairness. Use PeerJS with a room code ("enter friend's 6-letter code"). Effort: **Medium** (lobby UI, disconnect handling, rematch). This is the best online feature for the effort.
- **Online co-op shooter**: use delay-based lockstep with 2–4 frames of input delay, exchanging per-tick inputs on an unordered or reliable channel, plus periodic state hash checks. It needs the same determinism work as ghost replays. Alternatively use a host-authoritative model (host simulates, guest sends inputs and receives state snapshots), which avoids determinism but makes the guest feel lag. Effort: **High**. Rollback: **High+**, not recommended for a solo developer.
- Signalling choice: the PeerJS cloud server is easiest (zero infrastructure), but it is a third-party dependency with no SLA (see Gaps). Copy-paste SDP is fully serverless but awkward. Offer it as a fallback "Advanced: connect manually" option, best for two people in the same chat. Free public STUN (for example Google's) is commonly used. TURN is not free, so expect about 10–25% of pairs (more on mobile data) to fail and show a clear "couldn't connect — try the same Wi-Fi" message.

### Gaps
- Could not retrieve authoritative terms, rate limits or uptime for the free PeerJS cloud server (0.peerjs.com) from its docs or README. Treat it as best-effort and verify current status before relying on it.
- No source found on measured WebRTC data-channel latency in Android WebView, or on free TURN offerings and their terms in 2024–2026.

## Free or zero-cost leaderboard options without running a server, and trade-offs (privacy, abuse)

### Takeaway
Hosted free tiers (Firebase Spark/Firestore, dreamlo, and similar) can provide a global board without your own server, but every client-written score is forgeable, quotas can take the board offline, and they add data-collection obligations. For a friends-focused game, a local plus "friends via share codes" board is safer and fits the no-server constraint better than a public global leaderboard.

### Cited Findings
- dreamlo: a free, non-commercial hosted leaderboard using plain HTTP GET (name, score, seconds, extra text). HTTPS reportedly requires a small (about $5) donation, which matters for HTTPS pages and Android. Without it, scores can be faked easily. Default setup lets players flood the board by changing names. Developers report outages, including a multi-day one — [Unity Asset Store: dreamlo](https://assetstore.unity.com/packages/tools/network/dreamlo-com-free-instant-leaderboards-and-promocode-system-3862); [Unity forum](https://forum.unity.com/threads/dreamlo-not-working-with-webgl.634462/); [itch.io helper script](https://milkshakebattlecat.itch.io/dreamlo-helper-script)
- Firebase Spark (free): about 50K Firestore reads/day, 20K writes/day, 1 GB storage (third-party summaries). Reads are per document, and the quota resets at midnight Pacific. When exhausted, the service stops for everyone until reset (no bill) — [back4app](https://blog.back4app.com/firestore-pricing/); [rapidevelopers](https://rapidevelopers.com/ai-build-errors/quota-exceeded-for-firestore-reads)
- Firebase App Check attests the app or device, not the score. The docs state it "does not guarantee the elimination of all abuse". Proper validation needs server-side code (Cloud Functions), which on Firebase requires the paid Blaze plan — [Firebase App Check](https://firebase.google.com/docs/app-check); [dev.to Spark vs Blaze](https://dev.to/androve2k/spark-vs-blaze-the-firebase-pricing-guide-i-wish-id-read-sooner-onb)

### Inferences
- Recommended tiering:
  1. **Local leaderboard** (localStorage, per mode, initials entry, arcade-style top 10) — **Low**.
  2. **Friends board from shared codes**: when a friend's challenge or result code is opened, store it locally as a "rival" entry, to build a personal friends leaderboard with no server — **Low–Medium**.
  3. **Global board on a free hosted service**: only with caveats. Show a public-name-only notice, filter or cap name length, rate-limit by client, sanity-check scores (max plausible score per minute), and accept that cheaters will appear. Firebase's daily read quota means caching the top-N and fetching on demand. Effort: **Medium**, plus ongoing moderation.
- Privacy: a global board collects names (possibly real names) and IP addresses at a third party. That needs a privacy note for the Play Store data-safety form. Local and share-code approaches avoid this entirely.

### Gaps
- Official Firebase pricing page not directly fetched. Quota numbers come from third-party summaries and should be verified.
- Did not evaluate other free options (Supabase free tier, itch.io, Google Play Games Services leaderboards for the Android wrapper, LootLocker etc.) due to the tool-call budget.

## Party features (local tournaments/brackets, handicaps, quick rematch, versus stats)

### Takeaway
Competitive Tetris games expose rule toggles and difficulty "mods" that double as handicaps, and they minimise downtime between rounds (instant retry, rejoin right after elimination). These patterns transfer directly to local play. Brackets and versus stats are pure UI and local storage, so cheap to build, but no source was found measuring their impact.

### Cited Findings
- TETR.IO custom rooms let the host adjust rules per room (combo system, B2B, spin bonuses, preview count, opener phase), and QUICK PLAY offers opt-in harder "mods" (No Hold, Messier Garbage, Invisible, Double garbage). TETR.IO lets players jump into a new QUICK PLAY run right after elimination, and its retry key needs only a tap in solo modes — [TetrisWiki: TETR.IO](https://tetris.wiki/TETR.IO)
- Tetris 99's badge system rewards knocking out leaders (stealing badges) and increases attack power, a built-in comeback/kingmaker dynamic for groups — [Shacknews](https://shacknews.com/article/110011/tetris-99-controls-how-to-play-and-strategy); [Destructoid](https://www.destructoid.com/the-depth-of-tetris-99s-mechanics-do-the-impossible-improve-a-perfect-game/)
- Daily-run developers note that unlimited attempts are "more welcoming" while single attempts raise stakes, which is relevant to choosing party rules — [Game Developer](https://www.gamedeveloper.com/design/the-24-hour-ticket-examining-daily-runs-)

### Inferences
- **Quick rematch**: on versus game-over, show "A = Rematch / B = Menu" with the score tally carried over (first to 3 wins), and swap seeds each round. Effort: **Low**.
- **Handicaps** (per player, chosen in lobby): Tetris — starting level/gravity, garbage multiplier (0.5x–1.5x), hold on/off, preview count. Shooter — extra lives, fire rate, shield, score multiplier. Present them as named "mods" like TETR.IO's to avoid stigma. Effort: **Low–Medium**.
- **Local tournament / "pass-the-phone" party mode**: enter 2–8 names, then either (a) score-attack rounds where everyone plays the same seed in turn and a ranking table updates, which works on one phone and in both games, or (b) a single-elimination bracket of versus matches (needs 2-player local versus). Effort: **Low** for (a), **Medium** for (b).
- **Versus stats**: persist head-to-head records per name pair (wins, best attack, longest combo, APM) in localStorage, plus a post-match "awards" screen (Most Tetrises, Garbage King, Clutch Survivor). Effort: **Low**.
- **Shooter party twist**: a "steal the dual fighter" rule in co-op (a captured ship can be rescued by either player) and a shared-lives pool create the cooperative or competitive tension that the original capture mechanic implies.

### Gaps
- No sourced evidence (studies, postmortems, GDC talks) quantifying how rematch flow, handicaps, brackets or versus stats affect fun or retention among friends. Recommendations here are design inferences from how TETR.IO and Tetris 99 structure play.
- No source retrieved on Puyo Puyo Tetris or Jstris handicap/rematch UX specifically.
